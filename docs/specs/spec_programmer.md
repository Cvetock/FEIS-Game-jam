# Спецификация: Программист
## Проект: ПОСЛЕДНИЙ ЧЕЛОВЕК

## Твоя роль в команде
Ты отвечаешь за весь код игры. Игра работает в браузере (HTML5 Canvas 2D), без шага сборки, без библиотек. Твоя задача — сделать так, чтобы вся логика агентства, собеседований, заданий, нечестных отчётов, overkill, конкурентов и финального тендера работала без критических багов.

## Стек (обязательно)
- Чистый JavaScript (ES2020+)
- HTML5 Canvas 2D
- Без Node/npm, без сборщиков, без внешних библиотек
- Запуск: двойным кликом по `index.html`

## Что именно ты должен сделать

### День 1 — Каркас и ядро
1. **Структура проекта** (уже частично готова из подготовительной фазы):
   - `index.html` — точка входа
   - `src/main.js` — игровой цикл, состояния (меню / агентство / задание / отчёт / конец дня)
   - `src/game.js` — менеджер состояний игры
   - `src/input.js` — мышь, клавиатура, тач
   - `src/renderer.js` — отрисовка экранов, UI-элементы (кнопки, списки, прогресс-бары)
   - `src/assets.js` — загрузка картинок и звуков
   - `src/audio.js` — Web Audio API (SFX + музыка)
   - `src/utils.js` — утилиты (случайные числа, статы, расчёт результатов)
2. **Модель данных:** классы/объекты для:
   - **Монстра:** имя, вид, статы (сила, ловкость, интеллект, удача), черта, **предпочтение (preference)**, статус
   - **Задания:** название, сложность, награда, риск, требуемый вид, **перехвачено (boolean)**
   - **Предмета:** тип, бонусы
   - **Агентства:** уровень, улучшения (стойла, кузня, канализация, крипта, тренировочный зал, отдел разведки, школа лжи), золото, угроза героев
   - **Игрового состояния:** день, штат монстров, доступные кандидаты, доска заказов, история отчётов
   - **Результата задания:** тип (успех / частичный успех / overkill / неудача / исчезновение), золото, угроза, травма, **отчёт монстра (текст, честный/ложный)**
3. **Генерация монстров:** случайные имя, вид, статы (1–20), черта, **предпочтение (preference)**.
4. **Генерация заданий:** случайные название, сложность, награда, риск, **перехвачено = threat × 0.1 (или 0.05 с разведкой)**.
5. **Экран агентства:** список монстров в штате, **кандидаты на собеседование (3 в день)**, доска заказов (с индикатором «Перехвачено»), кнопка «Нанять» (проверка предпочтения), кнопка «Отправить на задание».

### День 2 — Логика заданий, отчётов, конкурентов и роуглайк
1. **Система заданий:** выбор монстра + задания → авто-расчёт результата (статы + экипировка + случайность) → определение типа результата (успех / частичный успех / **overkill** / неудача / исчезновение).
2. **Overkill:** если результат превышает сложность на 50%+ → +150% золота, +1 угроза, 30% шанс травмы.
3. **Отчёт монстра (Unreliable Narrator):** генерация текста отчёта на основе шаблонов (`docs/content.md`). Честность = f(интеллект):
   - Интеллект ≥ 14: 100% честный
   - Интеллект 8–13: 50% честный
   - Интеллект ≤ 7: 10% честный
   Игрок видит только текст отчёта, не истинный результат.
4. **Экраны отчёта:** показ текста отчёта монстра, истинный результат виден только в логах/статистике (для отладки).
5. **Между днями:** трата золота на улучшения агентства (стойла, кузня, канализация, крипта, тренировочный зал, **отдел разведки**, **школа лжи**).
6. **Роуглайк-прогрессия:** уровень агентства растёт, **угроза героев растёт каждые 2 дня** (10% → 20% → 30% → 40%+), шанс перехвата заданий пересчитывается.
7. **Финальный тендер (День 14 / уровень 5):**
   - Появляется «Герой-Директор» с собственным набором монстров.
   - Общее финальное задание. Игрок и ИИ выбирают монстров.
   - Сравнение отчётов по скрытым критериям (качество + честность + предпочтения).
   - Победа/поражение на основе тендера.
8. **Условия победы/поражения:** выжить 14 дней + выиграть тендер, или город теряется (угроза ≥ 100% / нет монстров / проигрыш в тендере).

### День 3 — Полировка и билд
1. **Багфиксы:** исправить все критические баги (игра не запускается, не сохраняет progresс, не считает результаты).
2. **Локальное хранилище:** опционально — сохранение прогресса между перезагрузками (`localStorage`).
3. **Билд для itch.io:** собрать все файлы в одну папку, проверить, что `index.html` работает без сервера.
4. **README:** как запустить игру (просто открыть `index.html`).

## Технические ограничения
- Не более 3-4 видов монстров в MVP.
- Не более 15 типов заданий.
- Не более 8-10 карт улучшений агентства.
- Нет сложной анимации — статичные спрайты + простые эффекты (мигание, появление текста).

## Файлы, с которыми работаешь
- `index.html` — точка входа (уже есть)
- `src/*.js` — весь код (уже есть базовый каркас, нужно адаптировать под концепт)
- `docs/balance.md` — формулы от капитана (взять у капитана)
- `docs/content.md` — шаблоны отчётов, предпочтения, имена (создаёт капитан)

## Взаимодействие
- С капитаном: утверждаешь формулы баланса, показываешь прототипы.
- С художником: интегрируешь спрайты в UI, подгоняешь размеры.
- Со звукорежиссёром: интегрируешь звуковые события (кнопка, отправка, возвращение, улучшение, overkill, ложь, перехват, тендер).
- С QA: исправляешь баги из чек-листа тестирования.
