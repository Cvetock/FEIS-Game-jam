# Спецификация: Программист
## Проект: ПОСЛЕДНИЙ НПС

## Твоя роль в команде
Ты отвечаешь за весь код игры. Игра работает в браузере (HTML5 Canvas 2D), без шага сборки, без библиотек. Твоя задача — сделать так, чтобы вся логика гильдии, экспедиций и роуглайк-прогрессии работала без критических багов.

## Стек (обязательно)
- Чистый JavaScript (ES2020+)
- HTML5 Canvas 2D
- Без Node/npm, без сборщиков, без внешних библиотек
- Запуск: двойным кликом по `index.html`

## Что именно ты должен сделать

### День 1 — Каркас и ядро
1. **Структура проекта** (уже частично готова из подготовительной фазы):
   - `index.html` — точка входа
   - `src/main.js` — игровой цикл, состояния (меню / гильдия / экспедиция / отчёт / конец дня)
   - `src/game.js` — менеджер состояний игры
   - `src/input.js` — мышь, клавиатура, тач
   - `src/renderer.js` — отрисовка экранов, UI-элементы (кнопки, списки, прогресс-бары)
   - `src/assets.js` — загрузка картинок и звуков
   - `src/audio.js` — Web Audio API (SFX + музыка)
   - `src/utils.js` — утилиты (случайные числа, статы, расчёт результатов)
2. **Модель данных:** классы/объекты для Волонтёра, Квеста, Предмета, Гильдии, Игрового состояния.
3. **Генерация волонтёров:** случайные имя, класс, статы (1–20), черты.
4. **Генерация квестов:** случайные название, сложность, награда, риск.
5. **Экран гильдии:** список волонтёров, доска квестов, кнопка отправки на экспедицию.

### День 2 — Логика экспедиций и роуглайк
1. **Система экспедиций:** выбор волонтёра + квеста → авто-расчёт результата (статы + экипировка + случайность) → отчёт.
2. **Экраны отчёта:** успех / частичный успех / неудача / травма / исчезновение.
3. **Между днями:** трата золота на улучшения гильдии (кузница, таверна, библиотека, тренировочный зал).
4. **Роуглайк-прогрессия:** уровень гильдии растёт, угроза монстров растёт каждые 2 дня.
5. **Условия победы/поражения:** выжить 14 дней или город падает.

### День 3 — Полировка и билд
1. **Багфиксы:** исправить все критические баги (игра не запускается, не сохраняет progresс, не считает результаты).
2. **Локальное хранилище:** опционально — сохранение прогресса между перезагрузками (`localStorage`).
3. **Билд для itch.io:** собрать все файлы в одну папку, проверить, что `index.html` работает без сервера.
4. **README:** как запустить игру (просто открыть `index.html`).

## Технические ограничения
- Не более 3-4 типов волонтёров в MVP.
- Не более 15 типов квестов.
- Не более 8-10 карт улучшений гильдии.
- Нет сложной анимации — статичные спрайты + простые эффекты (мигание, появление текста).

## Файлы, с которыми работаешь
- `index.html` — точка входа (уже есть)
- `src/*.js` — весь код (уже есть базовый каркас, нужно адаптировать под концепт)
- `docs/balance.md` — формулы от капитана (взять у капитана)

## Взаимодействие
- С капитаном: утверждаешь формулы баланса, показываешь прототипы.
- С художником: интегрируешь спрайты в UI, подгоняешь размеры.
- Со звукорежиссёром: интегрируешь звуковые события (кнопка, отправка, возвращение, улучшение).
- С QA: исправляешь баги из чек-листа тестирования.
